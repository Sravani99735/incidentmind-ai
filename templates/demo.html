Incident 1: INC-0101 (The Initial Learning)

First Encounter

Payment API experiences HTTP 503 during promotional checkout surge. Database connection pool exhausts at 50 connections.

Outage Telemetry & Symptoms:
Symptoms: HTTP 503 Service Unavailable, PgBouncer pool exhausted (50/50)
Telemetry: active=50, idle=0, queue=284, Aurora DB host CPU=24% (healthy)
Action Taken:

Scaled connection pool from 50 to 100 in ConfigMap and restarted pods gracefully.

Knowledge Retained in Hindsight:
  • INC-0101: Payment API 503 caused by database connection pool exhaustion on Kubernetes.
  • INC-0101: Pool saturation showed active=50, idle=0, queue=284 with DB CPU healthy.
  • INC-0101: Increasing connection pool from 50 to 100 successfully resolved the outage.
Key Organizational Lesson:

Retained baseline: When DB CPU is low but pool queue is high, pool expansion works.
